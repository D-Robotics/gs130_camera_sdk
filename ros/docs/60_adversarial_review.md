## 2. 攻击与裁决

### A2-1 单线程定时器模型在 1080p 下不成立（A1 的 D-1，攻击我）

- **指控**：1920x1080 拼接帧 6.2 MB，30 fps 下拷贝 + DDS ≈ 373 MB/s；
  单线程 executor 会让图像回调阻塞 IMU 回调。判据：IMU 间隔 p99 > 2/odr 或图像速率 < 29.0 Hz 即否决。
- **裁决**：**部分成立，但实测未触发**。实验见 §3 phase 1。
  我保留单线程，但接受其"必须给出否决阈值"的要求，并把它写进测试判据。

### B2-1 `take_clock_offset()` 在 `use_sim_time` 下会算出巨大负 offset（B1，攻击我的实现）

- **指控**：实现用 `node->now()` 取时间，开启仿真时间后得到的是仿真时刻，
  与设备单调时钟相减得到一个无意义的巨大 offset，`header.stamp` 全错。
- **裁决**：**成立，是真实缺陷**。已修：启动时若 `use_sim_time=true` 直接 FATAL 拒绝并说明原因。
  实测：`ros2 run gs130_ros camera_node --ros-args -p use_sim_time:=true` →
  `use_sim_time is not supported: the camera stamps are monotonic since boot and cannot be
  mapped onto simulated time.`

### B2-2 `gs130_start()` 失败时句柄未销毁，相机会被残留持有（B1，攻击我的实现）

- **指控**：C++ 构造函数抛异常时析构函数**不会**执行，`device_` 泄漏，
  相机保持被占用——正是 E8 的成因。
- **裁决**：**成立，是真实缺陷且后果严重**（后续任何进程都拿不到相机）。已修：
  构造函数体包在 `try/catch` 中，失败即 `shutdown()` 释放再抛出。
  实测：故意用非法参数让启动失败后，`python3` 仍能成功 `gs130.Device(...)` 打开相机。

### C2-1 E2 的常规判据没有鉴别力（C1，攻击测试方案也攻击实现）

- **指控**：`len(data)==w*h*3/2`、`step==width`、`encoding=="nv12"` 这三个断言
  在错误的打包高（`H*3/2`）下**同样成立**，因此它们抓不住 E2 类缺陷；
  唯一有鉴别力的是 `height == SDK 的真实高`。
- **裁决**：**成立**。已把消息构造抽成可测纯函数 `to_image()`，
  并在 gtest 中断言 `height` 原样透传（而不是从缓冲长度反推）。

### C2-2 `odr` 缺少值域校验（C1）

- **指控**：冻结书只接受 200/500，实现只拒绝 `odr < 1`，`odr:=100` 很可能不 fail-fast。
- **裁决**：**成立**。已修，并把判据从"冻结书说"升级为**实测**：
  `odr=100` 实测被 SDK 拒绝（`GS130_UNSUPPORTED`），`odr=200`/`500` 可用。
  顺便发现实测 500 Hz 时节点内部计数为 505 Hz、200 Hz 时为 202 Hz。

### 附带发现（C1、A1 在源码中发现）

| 发现 | 处置 |
|---|---|
| 拼接模式下 SDK 只填 `frame[0].data`，`frame[1].data` 为空；SDK 的 FIFO disposer 也可能释放帧 | 实现只 `free` 返回的那一个指针（已在代码中如此），列为回归判据 |
| 两目时间戳**不相等**（源码：各自独立，差 ≤ 16.7 ms），而非上一轮观察到的"相等" | 实现按每帧自己的时间戳发布，天然正确 |
| 拼接帧时间戳取 FSYNC 绑定目（右目），不是左目 | 实现直接使用 SDK 返回的拼接帧时间戳，天然正确 |
| `CameraInfo.P[3]=0` 会让 stereo 消费者读到零基线；`hobot_stereonet` 依赖它 | 见 §4 未采纳项 |
| 冻结书声称 `width ≤ 1088`，与实测 1920x1080 可用冲突 | 以实测为准，已在 `41_contract_revision.md` 记录 |

## 4. 未采纳的攻击意见（附理由）

| 意见 | 不采纳的理由 |
|---|---|
| 把 `CameraInfo.P[3]` 填成 `-fx*baseline` 以便 stereonet 可用 | `hobot_stereonet` 接线本身是 v0.1.0 明确的非目标；填一个未经立体校正计算的 P 会给出"看起来有效"的错误值，比留 0 更危险。已在 README 与 `41_contract_revision.md` 记为后续项 |
| 可执行名应为 `gs130_camera_node`（A1 冻结） | 采纳现状 `camera_node`：节点名 `gs130_camera` 已唯一标识，再加包名前缀是冗余。已在文档统一 |
| 一次性 offset 的精度承诺应撤销（A1 的 D-3） | **不采纳**：实测拟合漂移 0.047 ms/min（约 2.8 ms/小时），承诺成立。但实验确实暴露出 IMU 投递延迟抖动约 25 ms，已写入 README 与 `62_drift_result.md` |
